# ShipRoxy — App Store / Play Store packaging

ShipRoxy is a server-rendered Express/EJS web app. Rather than a separate
native rewrite, the iOS and Android apps are thin [Capacitor](https://capacitorjs.com/)
shells that load the deployed web app in a native WebView, giving you a real
installable `.ipa`/`.aab` plus native icon, splash screen, and status bar
styling, with the option to add native APIs (push notifications, camera,
etc.) later without changing the backend.

This setup is **prepped now, not submitted**: the native projects, config,
and placeholder art are all in place so wiring up the final production URL
and app-store assets at launch time is a quick flip, not a from-scratch task.

## What's here

```
capacitor.config.json     # app id, app name, the URL the native shell loads, plugin config
resources/icon.png        # 1024x1024 master icon (placeholder art)
resources/splash.png      # 2732x2732 master splash (placeholder art)
ios/                       # generated Xcode project (Capacitor iOS platform)
android/                   # generated Gradle project (Capacitor Android platform)
scripts/generate-mobile-assets.js   # (re)generates all native icon/splash sizes from code
```

`ios/` and `android/` are committed like normal source (this is the standard
Capacitor workflow) — their own `.gitignore` files already exclude build
output, `Pods/`, `.gradle/`, `local.properties`, etc.

## Before you build for real

Three things are placeholders on purpose and need your real values before
building for TestFlight/Play internal testing or submission:

1. **Production URL** — `capacitor.config.json`'s `server.url` is currently
   `https://shiproxy.example.com`. Point it at your deployed Replit/custom
   domain (must be HTTPS). Then run `npm run mobile:sync` to push the change
   into both native projects.

2. **Bundle/application ID** — currently `com.shiproxy.app` in
   `capacitor.config.json`. This is the identifier used to reserve the app
   in App Store Connect / Google Play Console and **cannot be changed after
   your first release**, so confirm it before your first submission. To
   rename it: update `appId` in `capacitor.config.json`, then either
   re-run `npx cap add ios` / `npx cap add android` on a clean checkout, or
   use `npx capacitor-set-bundle-id` / rename manually (Android:
   `applicationId` in `android/app/build.gradle` and the package in
   `AndroidManifest.xml`; iOS: the Bundle Identifier in Xcode's target
   settings).

3. **App icon & splash art** — `resources/icon.png` and `resources/splash.png`
   are procedurally generated placeholders (a plain navy square with a white
   container glyph, generated by `scripts/generate-mobile-assets.js` with no
   image-processing dependency — see the comment in that file for why).
   Replace those two masters with real brand art, then run
   `npm run mobile:assets` to regenerate every platform-specific size from
   them (all the exact files/sizes each template expects are already wired
   up in the script).

## Building locally

Native builds happen outside this container - iOS requires Xcode on macOS,
Android requires Android Studio (or just the Android SDK + Gradle, both of
which are locally testable). This container has Node/Java/Gradle but no
Android SDK or Xcode, so it can generate and keep the native projects in
sync, but not produce a signed build.

```bash
npm run mobile:sync          # copy capacitor.config.json + web assets into ios/ and android/
npm run mobile:open:ios      # open ios/App/App.xcworkspace in Xcode (macOS only)
npm run mobile:open:android  # open android/ in Android Studio
```

From there it's the normal native workflow: set your signing team/keystore,
archive, and upload via Xcode Organizer / Android Studio's Play publishing
flow (or `fastlane`, if you set that up later).

## Store prerequisites (need your accounts, not something I can set up)

- **Apple**: an Apple Developer Program membership ($99/yr) to get a signing
  certificate + provisioning profile, and an App Store Connect listing.
- **Google**: a Google Play Console account ($25 one-time) and a signed
  upload key for the `.aab`.
- Both stores require store-listing content this repo doesn't have yet:
  screenshots, a privacy policy URL, and (for a marketplace handling
  payments/messaging) answers to Apple's and Google's data-safety
  questionnaires.

## Why a wrapped web view instead of a rewrite

Both stores generally accept a well-built WebView wrapper as long as it
doesn't feel like "just a bookmarked website" - native navigation chrome,
offline handling, and platform look-and-feel all count in your favor. The
web app already has a native-style bottom tab bar, safe-area handling, and
PWA meta tags for exactly this reason; the Capacitor shell adds the native
icon/splash/status-bar layer on top. If App Store review pushes back citing
[guideline 4.2](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality),
the usual fix is adding one or two native-only touches (push notifications
is the most common) rather than a rewrite.
